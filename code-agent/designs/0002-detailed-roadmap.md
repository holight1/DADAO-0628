## Authority Order (repeated from README)

1. Locked Wiki commit in `manifests/spec.lock.toml`.
2. Accepted ADRs and contracts in this repository.
3. Independent test vectors and interface tests.
4. Implementation and comments.

When a contract and the Wiki conflict, implementation stops and a change
process begins — no component may self-resolve the conflict.

## TDD Contract (mandatory for all phases)

**Principle: spec first, independent oracle, no bootstrapping from implementations.**

Before any LLVM or QEMU line is written, test vectors must exist. All expected
values in every vector must be hand-derived from `contracts/` or the locked Wiki
— never generated by running LLVM or QEMU.

### Vector Taxonomy

Five classes of test vectors, each targeting a distinct normative claim:

| Class | Source in spec.md | Quantity target |
|-------|-------------------|-----------------|
| **Encoding** | Appendix A mask/value + format fields | ≥1 per M1 opcode |
| **Legality** | §2.6 + per-instruction Legality rows | ≥1 per ILLI trigger |
| **Semantic** | §3–§6 instruction semantics | ≥1 normal case per opcode |
| **Boundary** | signed-min, signed-max, zero, carry, overflow | ≥1 per arithmetic/shift opcode |
| **Overlap** | src=dst register, dual-dest, multi-reg range | ≥1 per overlap-legal opcode |

Vectors for C-27 (conditional assignment snapshot) are deferred pending
Wiki confirmation. All others are mandatory before Phase 2 or 3 begins.

### Workflow

```
spec.md Appendix A (mask/value)
    │
    ├─→ DL-001c: tools/opcodes.yaml + validate_encoding.py
    │        (machine-readable oracle; make check catches Appendix A errors)
    │
    ├─→ DL-001d: schema + inventory + isa/*.yaml + validate_vectors.py
    │        (actual vector data, coverage matrix, and schema validator)
    │
    └─→ Phase 2: llvm-lit tests use encoding vectors as CHECK patterns
        Phase 3: QEMU semantic tests diff against semantic vectors
        Phase 4: interface tests assemble→execute→check (both classes)
```

### Ordering Rule

DL-001d (vectors) and DL-002a (ABI) are **parallel** — ABI decisions do not
affect ISA encoding/semantic vectors. DL-001c (encoding validator) should
complete before DL-001d begins, so `opcodes.yaml` is available as a reference
for generating vector YAML files. DL-001c does **not** validate vector YAML
files — that is DL-001d's validator (`validate_vectors.py`).

C-27 (conditional assignment overlap) does **not** block Phase 2 or Phase 3
start. Overlap vectors for csn/csz/csp/cseq/csne are explicitly deferred and
marked in inventory as `status: deferred (C-27)`. C-27 **must** be resolved
before the M1 Completion Gate.

## Phase 0.5A: Spec Normalization

**Prerequisites**: Phase 0.
**Blocks**: Phase 0.5B, Phase 1.
**Tasks**: DL-001a ✓, DL-001c, DL-001d, DL-002a.

Produce the Wiki-derived oracle documents, the machine-readable opcode table,

and QEMU.

DL-001d and DL-002a are **parallel**. DL-001c (encoding validator) must
complete first — `opcodes.yaml` serves as a reference for DL-001d's YAML
generator and as a `make check` gate.

### Deliverables

| File | Content | Task | Status |
|------|---------|------|--------|
| `contracts/isa/spec.md` | Register model, encoding, scalar instructions, memory, control flow (M1 scope) | DL-001a | ✓ v0.4.0 (Candidate) |
| `tools/opcodes.yaml` | Machine-readable opcode table derived from Appendix A (mask/value, fields, format) | DL-001c | pending |
| `scripts/validate_encoding.py` | Checks mask/value arithmetic and field-label consistency in `opcodes.yaml`; exits non-zero on error; `make check` gate | DL-001c | pending |
| `tests/vectors/schema.md` | YAML field spec for vector data files: mnemonic, class, encoding, input\_state, expected\_state, expected\_fault, wiki\_cite, notes | DL-001d | pending |
| `tests/vectors/inventory.md` | Per-opcode coverage matrix (which YAML files exist, class, deferred reason if any) | DL-001d | pending |
| `tests/vectors/isa/*.yaml` | **Actual test data**: one file per instruction group; each entry is a complete test case runnable by harness | DL-001d | pending |
| `scripts/validate_vectors.py` | Validates `tests/vectors/isa/*.yaml` against `schema.md` field spec; catches missing required fields and type errors; `make check` gate | DL-001d | pending |
| `contracts/abi/spec.md` | Non-variadic scalar calling convention, return registers, callee-saved registers, frame layout | DL-002a | pending |

### Exit Gates

- Each contract section carries a Wiki chapter citation.
- Every M1-included area has at least an outline entry; no area is silently empty.
- Every M1-excluded area references the scope matrix (not duplicated inline).
- Immediate ranges expressed as precise decimal min/max.
- `make check` runs `validate_encoding.py` against `tools/opcodes.yaml`; fails
  on mask/value inconsistency or field-label error.
- `make check` runs `validate_vectors.py` against `tests/vectors/isa/*.yaml`;
  fails on schema violation or missing required field.
- `tests/vectors/isa/*.yaml` contain ≥1 actual test case per M1 opcode per
  applicable class (encoding, legality, semantic, boundary, overlap).
  C-27 overlap cases are present with `status: deferred (C-27)` and a null
  `expected_state` — they are not silently absent.
- Phase 0.5B prerequisite: **ISA contract (`contracts/isa/spec.md`) accepted**
  by architecture review. DL-001d, DL-002a may still be in-progress when Phase
  0.5B begins; they must complete before Phase 0.5C (Spec Freeze).

### Tasks

- **DL-001a** ✓: ISA contract — `contracts/isa/spec.md` v0.4.0 (Candidate; pending acceptance).
- **DL-001c**: Encoding validator — `tools/opcodes.yaml` (extract from Appendix A)
  + `scripts/validate_encoding.py` (mask/value arithmetic checks) + `make check` gate.
  Scope: Appendix A only. Does not validate vector YAML files.
- **DL-001d**: Vector data + validator — `tests/vectors/schema.md`, `tests/vectors/inventory.md`,

## Phase 2: LLVM MC

**Prerequisites**: Phase 1, ISA contract (DL-001a) and ELF contract (DL-004a) accepted.
**Parallelizable with**: Phase 3 (see Early Integration Checkpoint below).
**Tasks**: DL-007a … DL-012a (estimated; refined at Phase 1 exit).

### Deliverables

- Triple `dadao-unknown-elf` registered and selectable by `llvm-mc` and
  `llvm-objdump`. (`llc` is not required; it is a Phase 5 deliverable.)
- Register definitions for RD, RB, RF, RA banks with reserved-register constraints.
- Instruction format TableGen records with operand classes and immediate constraints.
- Assembler: encodes M1 instruction set; rejects invalid fields and out-of-range immediates.
- Disassembler: round-trips every assembled instruction back to canonical text.
- Encoder: byte output matches independent vectors authored from `contracts/isa/spec.md`.
- ELF emitter: correct machine header per ADR-0003; M1 relocation records match
  `contracts/elf/spec.md`.
- `make build-mc` Makefile target builds LLVM MC tools and runs `llvm-lit`.

### Exit Gates (LLVM-side only; cross-QEMU validation belongs to Phase 4)

- All encoding vectors authored independently (not from LLVM output) pass
  `llvm-mc` encoding and `llvm-objdump` disassembly.
- Encoding tests consume concrete cases from `tests/vectors/isa/*.yaml`, checked
  against `tools/opcodes.yaml`; they are never bootstrapped from LLVM output.
- Negative tests cover all legality-class vectors: invalid register fields,
  immediate overflow, reserved encodings, immutable-register writes.
- Boundary vectors (signed-min, signed-max, zero, overflow) are included.
- Overlap vectors for C-27 (conditional assignment snapshot) are deferred until
  Wiki confirms the snapshot rule; all other overlap classes are covered.
- No test derives expected bytes from LLVM output; all come from `tests/vectors/`
  or `contracts/isa/spec.md`.
- `make build-mc` → `llvm-lit test/MC/Dadao/`: zero failures.

### Candidate Task Breakdown

- DL-007a: Triple, target registration, minimal build; `build-mc` target functional.
- DL-008a: Register TableGen and reserved-register model.
- DL-009a: Instruction formats, operands, TableGen.
- DL-010a: Assembler and encoder; independent vector validation.
- DL-011a: Disassembler; round-trip tests.
- DL-012a: ELF emission; M1 relocation tests.

## Phase 3: QEMU Scalar Core

**Prerequisites**: Phase 1, ISA contract (DL-001a) accepted, Test Machine ADR
(DL-003b) accepted.
**Parallelizable with**: Phase 2 (see Early Integration Checkpoint below).
**Tasks**: DL-013a … DL-018a (estimated).

### Deliverables

- RD/RB/RF/RA CPU state, widths, and reset values per ISA contract.
- Decodetree-based fixed-width instruction decode.
- Scalar integer and address instruction execution (SimRISC M1 subset).
- Big-endian instruction fetch and data representation.
- Aligned scalar load/store; explicit MALIGN reporting per ADR-0004 observable
  protocol.
- Compare, branch, jump, call, ret (RegRAS only).
- Bare-metal machine per ADR-0004: ROM/RAM map, exit port, pass/fail signature.
- State-dump facility (register file snapshot) callable by test harness.
- `make build-qemu` target builds QEMU and runs semantic, legality, boundary,
  overlap, and fault vectors applicable to QEMU.

### Exit Gates

- All semantic vectors execute with correct state-before/state-after; expected
  register states come from `tests/vectors/` (hand-derived from spec.md §3–§6),
  not from QEMU source or QEMU-generated output.
- Legality vectors confirm: ILLI instructions do not commit register writes or
  memory; PC stays at faulting instruction.
- Boundary vectors (signed-min, signed-max, zero, overflow) are covered for all
  arithmetic instructions.
- Source/destination overlap tests pass for all overlap-legal instructions.
  Conditional assignment overlap tests (C-27) remain deferred.
- Immutable-register-write vectors (rd0 destination, rb0 destination) produce ILLI.
- MALIGN fires for every misaligned width per ADR-0004 protocol; aligned
  accesses do not fault.
- Exit signature is deterministic; no test relies on timeout or log text.
- Invalid encodings produce an assertable guest-visible result per ADR-0004.
- `make build-qemu`: zero failures.

### Candidate Task Breakdown

- DL-013a: CPU state, reset, QEMU target skeleton; `build-qemu` target functional.
- DL-014a: Decodetree and decode scaffolding.
- DL-015a: Scalar integer instructions (SimRISC data subset).
- DL-016a: Address instructions, load/store, MALIGN per ADR-0004.
- DL-017a: Branch, jump, call/ret, RegRAS.
- DL-018a: Bare-metal machine, exit port, signature, test harness, state dump.

## Early Integration Checkpoint

**Trigger**: As soon as Phase 2 has one instruction working (DL-010a milestone)
AND Phase 3 has the same instruction executing in QEMU (DL-015a or DL-016a
milestone), the first interface test must be written and passing before either
Phase 2 or Phase 3 adds further instruction coverage.

This is not a separate Phase — it is a gate embedded in the Phase 2/3 expansion
cycle. Its purpose is to catch endian, PC, load/loader, exit, and tool-interface
errors before they accumulate across a full instruction set.

**Required evidence**: at least one `tests/interface/` test that assembles with
`llvm-mc`, loads into QEMU, executes, and checks the exit signature.

## CodeGen Feasibility Spike

**Timing**: During Phase 2/3 expansion, after Phase 1 completes and before
Phase 4 finishes. Does not need to wait for full M1.

**Purpose**: Prove that the GPRD/GPRB bank model is implementable in LLVM
SelectionDAG or GlobalISel before committing full Phase 5 implementation work.

**Required evidence** (non-production spike code, not merged):

MIR tests demonstrating that pointer argument, pointer arithmetic, load/store
address, FrameIndex, global symbol, COPY/PHI across banks, and call/return
operands do not lose bank classification. Spike result recorded in an ADR
(ADR-0007 or similar).

If the spike finds the model unworkable, Phase 5 scope and ABI contract are
revised before any production CodeGen code is written.

## Phase 5: Basic CodeGen

**Prerequisites**: M1 complete, ABI contract (DL-002a) accepted, CodeGen spike
accepted.
**Tasks**: DL-022a … DL-029a (estimated).

**Linking scope**: Phase 5 uses same-TU freestanding binaries only. LLD and
cross-object linking are deferred. A minimal linker script or raw binary format
sufficient for QEMU loading is acceptable.

### Deliverables

- LP64 DataLayout, big-endian, consistent with `contracts/abi/spec.md`.
- GPRD (integer i64) and GPRB (pointer) value types in ISelLowering.
- Non-variadic scalar calling convention: argument allocation, return registers,
  callee-saved registers, frame layout.
- i64 arithmetic and constants.
- Scalar load/store for all M1 memory widths.
- Scalar compare/branch.
- Direct call and return.
- Stack frame, FrameIndex elimination, spill/reload.
- Callee-save save/restore in prologue/epilogue.
- MIR tests: verify register class (`%0:GPRD` / `%0:GPRB`), not only mnemonic.
- Freestanding runtime tests: compile IR → same-TU object → QEMU → deterministic
  signature.
- `make test-codegen` Makefile target.

### Exit Gates

- MIR tests check register class annotations, not only opcode strings.
- Runtime tests produce deterministic pass signature in QEMU; no compile-only claims.
- All tested functions are non-variadic with scalar inputs and returns.
- At least one test of each type (arithmetic, load/store, branch, call/return)
  executes end-to-end in QEMU.
- `make test-codegen`: zero failures.
