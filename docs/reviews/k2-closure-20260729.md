# K2 bare-metal kernel-mode closure and K3 readiness

**Date**: 2026-07-29  
**Task**: KL-145a  
**Status**: PASS（独立 review 完成）  
**Scope**: ADR-0015 K2 only；未启动 K3

## 1. 结论

K2 的冻结范围已经形成完整、可重复、fail-closed 的双后端证据链：

- cooperative task context：135-word frame，包含 rb1～rb4、
  rd32～rd63、rb32～rb63、ra0～ra63 和 ASID/PTBR 绑定；
- preemptive trap context：198-word 栈窗，包含硬件 cg5 diagnostic、
  rd1～rd63、rb1～rb63、ra0～ra63，并验证跨 CFX E1 LIFO；
- PTBR/TLB protocol：同 ASID 双 root，`PTBR write → full-set invalidate
  → tlb_gen++ → translated load`；
- timer-driven composition：handler 透明返回同一 task，只设置
  `need_resched`；task/PTBR 切换在 escape 后的 cooperative boundary
  完成；
- QEMU 与 gem5 分别先过 guest fail-closed 和独立 host oracle，再做 raw
  normalized report cross-compare。

KL-145a closure runner 的 15/15 gate 全部 PASS。K2 可以关闭；K3 具备
立项条件，但 Linux port 尚未开始。

## 3. Negative sensitivity

负向不是“两个后端一起错所以算一致”：

- KL-141a 翻转真实保存后的 rd40 frame slot；
- KL-142a 翻转完整 trap frame 的 rd17 slot；
- KL-143a 与 KL-144a 省略真实 TLB invalidate，利用同 ASID/同 VA/双
  root 形成 stale hit；
- 每个 guest 都独立形成 `final_status=FAIL`、非零 mismatch；
- host oracle 仍坚持正向语义，不按 mutation 放宽 generation/value；
- 两后端各自 FAIL 后才记录 cross-backend 结果，不能相互豁免。

runner 的 `known-make-check-debt` gate 以预期 return code 2 和精确的 5 条
coverage 输出复测：根 `make check` 仍在既有 `validate-vectors` 单指令
coverage 门失败：

```text
COVERAGE MISSING: ldmo-ra

COVERAGE MISSING: cfx2rc

```

这 5 个 privileged/control 指令已经被 K1/K2 多指令结构化场景实际执行，
但尚未纳入普通 ISA YAML 的单向量 coverage 口径。KL-142a 已记录同一
缺口；KL-145a 复测确认未增加、未减少。它不阻断 K2 privileged closure，
但在后续不能把整个根仓描述为 `make check` 全绿。

## 5. K3 readiness 与停止点

K3 开始时可以直接消费以下已冻结资产：

- ABI task/trap frame layout 与 RegRAS 保存恢复顺序；
- trap/escape ownership 和 timer acknowledge 规则；
- PTBR/TLB switch ordering 与 generation invariant；
- QEMU/gem5 FullSystem 同镜像 transport；
- guest report、独立 oracle、negative mutation 与 cross-compare runner。

但 K2 PASS **不等于 Linux 能启动**。进入 K3 后仍须从零完成：

1. Linux 版本 pin、可重复 fetch/build 与新 `arch/dadao` 骨架；
2. reset/entry/linker/early console；
3. Linux trap entry、irqchip、clocksource/clockevent API 对接；
4. Linux `switch_to`/`copy_thread` 与真实 task layout；
5. `pgtable.h`、paging init、page-fault policy 和 MMU/IO 映射时序；
6. user mode、ELF/initramfs/syscall，最终到 musl `/init`。

本任务停止在这里：manifest 中 Linux 仍为 `enabled=false`、commit 为空，
`components/linux/patches/series` 为空，没有创建或修改 `arch/dadao`，
没有拉取或改写 Linux tree。

## 6. Non-claim

K2 不声称：

- user↔supervisor、真实 process/user context、RF；
- Linux scheduler/trap/clockevent/irqchip/pgtable/page-fault API；
- Atomics/SMP、多 hart、真实 PLIC/UART/device protocol；
- initramfs、ELF `/init`、fork/exec/signal；
- gem5 Minor/O3、TLB timing/performance 或系统性能。

## 7. 独立 review

R1 发现 4 个 medium 与 2 个 low：

- 轮次只计数、负向字段分散匹配，可能接受重复轮次/SKIP；
- Linux patch boundary 未从 manifest 消费且未递归检查；
- 受测 backend binary 与 clean source tree 未绑定；
- review 时 summary 早于最新 runner；
- `make check` 缺少本任务日志；
- roadmap 尚未写 closure。

修复后 runner 增加 ordered `1..N`、单行绑定双 backend 非零 mismatch、
显式拒绝 SKIP、前置 backend/config binding、manifest-derived recursive
patch check、known-debt gate，并完整重跑生成 15/15 最新 summary；roadmap
同步收口。

focused R2 用 duplicate/out-of-order round、SKIP injection、split
negative、backend override、nested patch payload 与 alternate series
mutation 验证均为 FAIL。最终结论：**PASS，无 blocker/medium/low。**
